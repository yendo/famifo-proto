# 撮影者で一覧を絞り込む

## 目的

一覧を撮影者（ファイルの所有者の uid）で絞り込めるようにする。撮影者は複数選べて、
選んだ誰かが撮った写真を並べる。何も選ばなければ全員である。

将来は次の条件も同じ仕組みで足す。今回の設計はこれらを組み合わせて掛けられる形に
するが、実装は撮影者だけである。

- お気に入りのみ（オン/オフ）
- アーカイブも表示（オン/オフ。既定は隠す）
- 地域（複数選ぶ）

条件は組み合わせて使う前提である（例: 撮影者が A か B で、お気に入りのみ）。

## 決めたこと

- 絞り込む「ユーザー」は撮影者（`owner_uid`）である。ログイン中の人と uid の対応は
  持たない。「自分の写真」を既定にするのは、その対応ができてから上に足す。
- 値を選ぶ条件は、どれも複数選べる。節の中は OR、節どうしは AND でつなぐ。
  撮影者と地域で「1 つだけ」と「複数」を混ぜると、押したときの動きが節によって
  変わるため、そろえる。
- 選択肢に並べるのは、`owner.Name` で名前が引ける uid だけ。名前の無い uid の写真は
  撮影者で絞らないときにだけ見える。名前の無い uid をまとめる「不明」の項目は作らない。どの uid が
  不明に当たるかは配信時の passwd で決まり、URL に書いた条件と食い違いうるため。
- 絞り込みは URL のクエリ（`?owner=<uid>&owner=<uid>`）だけで持つ。最後の選択を
  覚えておく機能は作らない。開き直せば絞り込みの無い一覧に戻る。
- URL の値は uid のまま。username にすると要求ごとに逆引きが要り、DSM 側で
  username と uid の対応が変わると同じ URL が別の人を指す。
- `chown` には追従しない（[2026-10-14-photo-owner-design.md](2026-10-14-photo-owner-design.md)
  のまま）。持ち主を変えたら DB を作り直す。直すまで、別の人の一覧に写真が混ざる。

## 設計

### store

```go
// Filter は一覧の絞り込み。各フィールドは 1 つの条件で、指定したものをすべて満たす
// 写真に絞る。ゼロ値は普段の一覧である。
type Filter struct {
	Owners []uint32 // 持ち主の uid のどれか。空なら持ち主で絞らない
}

func (s *Store) Count(ctx context.Context, f Filter) (int, error)
func (s *Store) DayGroups(ctx context.Context, f Filter) ([]DayGroup, error)
func (s *Store) ListRange(ctx context.Context, f Filter, offset, limit int) ([]media.Media, error)
func (s *Store) RankOf(ctx context.Context, f Filter, id string) (int, error)
func (s *Store) Owners(ctx context.Context) ([]uint32, error)
```

- `Filter` は呼び出し側が構造体リテラルで一度に組み立てる。条件を 1 つずつ足す
  メソッド（`WithOwner` など）や、全条件を引数に取る `NewFilter` は採らない。前者は
  条件を積んでいくように読めるが、実際は URL の条件の組を一度に掛けるだけである。
  後者は条件が増えると引数が位置だけで並び、増えるたびにシグネチャが変わる。
- 「指定なし」は空のスライスで表すので、uid 0（root）と取り違えない。
- 絞り込んだ「見え方」を返す型（`s.View(f).Count(ctx)`）は採らない。型が `Filter`
  と合わせて 2 つになり、`Store` と見え方のどちらに何を置くかの分担が要る。ハンドラは
  1 つの要求で 1 つの `f` を使い回すだけなので、得るものが少ない。
- WHERE 句は `Filter` の非公開メソッド 1 つが作る。撮影者は `owner_uid IN (?, …)`
  で、条件どうしは `AND` でつなぐ。4 つのメソッドはこれを差し込むだけにして、
  総枚数・日ごとの並び・チャンク・位置が同じ条件からずれないようにする。
- `RankOf` は、id の写真が `f` に当てはまらなければ `ErrNotFound` を返す。前に並ぶ
  件数も同じ条件で数える。
- `Owners` は写真のある uid を重複なしで小さい順に返す。名前を引くこと、名前の無い
  uid を落とすこと、名前順に並べることは web の仕事である。
- 表も索引も変えない。持ち主で絞ると、SQLite は既存の索引を読みながら行の
  `owner_uid` で振り分ける。4497 枚の実データでは全件を読んでもミリ秒単位で、
  持ち主を含む索引を足しても体感の差は出ない。2 人以上を選べばその索引は使われず、
  書き込みのたびに更新する索引が増えるだけなので、足さない。遅くなったら測って
  から足す。

将来の条件はフィールドとして並ぶ。地域は `Regions []string` のように同じ形になる。
アーカイブは既定で隠すので、ゼロ値が普段の表示になる向きで `IncludeArchived bool`
のように名付ける。

### web

#### 条件の読み取りと URL

- `filterFrom(r) (store.Filter, error)` が `?owner=` をすべて読む。どれか 1 つでも
  `uint32` の数値でなければ 400 を返す。重複は落とし、小さい順に並べる。
- 今の条件を引き継ぐ URL（チャンク、個別表示、閉じて戻る先）は、`filterURL` が
  作る。値は小さい順に並べて書くので、同じ条件の組は同じ URL になる。JS は条件の
  組み合わせを知らない。
- 条件を変えるときは、サイドバー（シート）の GET のフォームをブラウザが送る。
  すべての節のチェックボックスが同じフォームに入っているので、条件の組み合わせは
  ブラウザが作る。値の並びは画面の並び（名前順）になるが、`filterFrom` が並べ直して
  読むので結果は変わらない。
- ログイン前に開いた URL のクエリは、`requireSignIn` が `RequestURI` を `next` に
  入れるので、ログイン後も残る。

#### ハンドラ

- `/` と `/item/{id}` は `Count`・`DayGroups`・`RankOf` に `f` を渡す。トップバーの
  「N 件」は絞り込んだ件数になる。
- `/item/{id}` で写真が `f` に当てはまらない（無い、または選んでいない人の写真）
  ときは、今と同じく一覧へリダイレクトする。行き先は `/` ではなく、絞り込んだ
  一覧である。
- `/tiles` は `ListRange` に `f` を渡す。各タイルの `pageUrl` は
  `/item/{id}?owner=<uid>&…` になり、個別表示で前後に送っても絞り込みの中に
  留まる。
- `?owner=` に選択肢に無い uid（名前の無い人など）を直接書いた場合も、URL の
  とおりに絞り込む。サイドバーではその uid の項目が無いので、チェックは見えない。

#### JS に渡す URL

今の JS には、絞り込みが落ちる場所が 3 つある。どれもサーバーが絞り込み込みで作った
URL を渡す形に揃える。

| 場所 | 今 | 変更後 |
| --- | --- | --- |
| chunk.js のチャンク取得 | `/tiles?chunk=N` を組み立てる | `#gallery` の `data-tiles`（例 `/tiles?owner=1026`）に `URLSearchParams.set("chunk", N)` で足す |
| タイルの `pageUrl` | `/item/{id}` | `/item/{id}?owner=<uid>&…`（上記） |
| lightbox.js の閉じる処理 | `"/"` へ戻す | `#gallery` の `data-home`（例 `/?owner=1026`）へ戻す |

絞り込まないときは、それぞれ `/tiles` と `/` である。

### 画面

PC は左のサイドバー、スマホは下から出るシートにする。Google Photos や Synology
Photos のサイドバーは画面の切り替え（お気に入り、アーカイブなどが別の画面）だが、
ここでは条件を並べ、組み合わせて掛けられるようにする。スマホで左から出る
ドロワーは、今のアプリではあまり使われないので採らない。

- 絞り込みのパネルは 1 つの要素で、中身は条件ごとの節を並べる。今回は「撮影者」の
  節だけ作る。名前の引ける撮影者が 1 人もいなければ（`/etc/passwd` を
  マウントしていないなど）、節ごと出さない。
- パネルは一覧への GET のフォーム（`<form method="get" action="/">`）で、節は
  `<fieldset>` である。
- 撮影者の節は、`Owners` の uid に名前を引いて名前の無いものを落とし、名前順に
  並べた項目である。
  - 各項目は、左に名前、右端にチェックボックス（`name="owner"`、値は uid）を置く。
    選んでいる人にチェックが付く。チェックを文字の前に置くと、付け外しのたびに
    名前の位置が動くので、右端に寄せる（Synology Photos の Quick Filter に倣う）。
  - 何もチェックしなければ撮影者で絞らない。「全員」の項目は置かない。
  - チェックを変えると filters.js がフォームを送る。チェックボックスは変えた
    だけでは何も送らないためである。
  - ページごと読み直すので、チャンクのキャッシュや日ごとの並びを捨てる処理は
    要らない。
- 画面幅での出し分けは CSS だけで行う。境目は既存の `@media (min-width: 1100px)`
  に合わせる（iPad の横向きはサイドバー、縦向きはシート）。
  - 広い画面: パネルを左に `position: sticky` のサイドバーとして常に出す。
  - 狭い画面: パネルを画面下に固定したシートにして、普段は隠す。トップバーの
    絞り込みボタンで開け閉めする。JS はクラスを 1 つ付け外しするだけである。
- 見出しと項目は同じ大きさにし、見出しは太字で分ける。
- 絞り込みボタンは狭い画面でだけ出す。パネルに節が 1 つも無ければ、ボタンも
  サイドバーも出さない。条件が 1 つでも掛かっていれば目立つ色にする。何が
  掛かっているかは、シートを開けば分かる。広い画面ではサイドバーのチェックで分かる。
- 掛かっている条件をチップの列で見せる案は採らない。トップバーの中に置くと
  トップバーが `--topbar-h` より高くなり、`top: var(--topbar-h)` のスクラバーが
  チップに重なる。掛かっているかどうかが分かれば足りるので、ボタンの色で伝える。

レイアウトの計算は変えずに済む。列数と列幅は `#layoutprobe` のグリッドの計算結果
から読み、一覧の上端は `#spacer` の位置を測り、幅の変化は `ResizeObserver` が
拾う。サイドバーで幅が狭くなれば、その幅で列数が決まる。

## テスト

いずれも公開 API 経由で書く。

- store
  - 3 人分の写真を入れ、`Filter{Owners: []uint32{a}}` と
    `Filter{Owners: []uint32{a, b}}` で `Count`・`DayGroups`・`ListRange` が
    選んだ人の分だけを返す
  - `Filter{}` では今までどおり全件を返す
  - uid 0 の写真を `Filter{Owners: []uint32{0}}` で絞れる
  - 1 人と 2 人の絞り込みのそれぞれで、`RankOf` と `ListRange` の位置が一致する
    （`TestRankOfLocatesTheItemInListRange` を絞り込みでも回す）
  - 選んでいない人の写真の id を `RankOf` に渡すと `ErrNotFound`
  - `Owners` が写真のある uid だけを返す
- web（`httptest` で `Handler` を叩く）
  - `/?owner=a&owner=b` で件数と DayGroups が 2 人の分になる
  - `/tiles?owner=` の各タイルの `pageUrl` に条件が付く
  - `data-tiles` と `data-home` が絞り込みを含む
  - 選んでいない人の写真を `/item/{id}?owner=` で開くと、絞り込んだ一覧へ
    リダイレクトされる
  - 数値でない `owner` が 1 つでもあれば 400
  - `?owner=b&owner=a&owner=a` と `?owner=a&owner=b` で、サーバーが作る URL が同じになる
  - パネルは一覧への GET のフォームで、撮影者の節に名前の無い uid が出ず、名前順に
    並び、選んでいる人のチェックボックスにチェックが付く。「全員」の項目は無い
  - 誰も選んでいなければ、どれにもチェックが付かない
  - 名前の引ける撮影者がいなければ節が出ない
- ブラウザテスト
  - 広い画面ではサイドバーが常に出ていて、チェックを入れるとその人の写真だけが並び、
    読み直した後もチェックが残る
  - 狭い画面では絞り込みボタンでシートが開き、チェックを入れるとその人の一覧になる
  - 絞り込み中は絞り込みボタンが目立つ色になる
  - 絞り込んだまま個別表示で前後に送ると、選んだ人の写真の中だけを動く
  - 個別表示を閉じると絞り込んだ一覧に戻る

## 運用

- 表も索引も変わらないので DB の作り直しは要らない。
- 撮影者の名前を出すには、これまでどおりコンテナに `/etc/passwd` を `:ro` で
  マウントする。しないと撮影者の節は出ない。
