# 全画面表示の骨格（帯の出し入れと左下の情報）

## 目的

全画面表示（ライトボックス）に情報やボタンを足していく前に、それらの置き場所と
出し入れの仕組みを決める。発端は撮影者の名前の位置で、上端の中央は見にくく、
左下に移すと動画の標準コントロールと重なった。要素ごとに重なりを避けていくと、
項目が増えたときに破綻する。

今後出したいものは次のとおり。

- 撮影者、日時、撮影場所
- 戻る矢印、前・次の写真へ送るボタン
- 情報ボタン、お気に入りボタン、メニュー

## 範囲

この設計で実装するのは、今あるデータと機能で作れるものだけである。

- 帯（ボタンと左下の文字）をタップで出し入れする仕組み
- 戻る矢印、前・次のボタン
- 左下の撮影者と日時
- 動画の標準コントロールとの連動

撮影場所、お気に入り、情報、メニューは置き場所だけをここで決め、それぞれ別に
設計する。押しても何も起きないボタンは置かず、機能ができたときに足す。

- 撮影場所は EXIF の GPS の取り込みと、緯度経度から地名を引く方法が要る。
- お気に入りは、誰のものか、どこに保存するかの設計が要る。
- 情報パネルは、今ある情報だけでは左下に出すものとほぼ同じになる。
- メニューは中身が決まっていない。

日時のロケール対応もしない。一覧の日付ラベルと同じ日本語の書式で出し、
ロケール対応は一覧と合わせて別に行う。

## 他のアプリの作り

Apple の写真、Google フォト、Synology Photos などは、情報とボタンを写真に浮かべず
上下の帯にまとめ、タップ（PC ではマウスの動き）で帯ごと出し入れする。動画の
コントロールは自前で描いて帯の一部にしている。詳しい情報は上スワイプや情報ボタンで
開く別のパネルに置き、PC では右、スマホでは下から出す。

famifo は動画のコントロールを自前で作らず、ブラウザ標準のものを使う。理由と
その帰結は「動画」の節に書く。

## 配置

```
+--------------------------------+
| <-                fav  i  menu |   上: 戻る / お気に入り / 情報 / メニュー
|                                |
| <                            > |   前・次（PC のみ）
|                                |
| owner                          |   左下 1 行目: 撮影者
| date-time, place               |   左下 2 行目: 日時 · 場所
+--------------------------------+
```

- ボタンはすべて上に置く。下は左に文字があり、動画のときは標準コントロールも来る。
- 右上の並びは、よく押すものほど内側にする。メニューは中身が増えても端に置けば
  並びが崩れない。今回置くのは戻る矢印だけである。
- 左下の 1 行目は撮影者、2 行目は「日時 · 場所」。場所ができるまでは日時だけを出す。
- 前・次のボタンは `(hover: hover)` の端末（PC）だけに出す。左右の端の上下中央に
  置く直径 44px の丸いボタンで、押せる範囲はボタンの大きさだけにする。タッチ端末では
  出さず、左右スワイプで送る。
- 文字には背景も影も付けない。ボタン（戻る、前・次）には丸い半透明の黒い背景を付ける。

## 操作

lightbox の `chrome` クラスが、帯（上のボタン、左下の文字、前・次のボタン）を
出しているかを表す。開いたときは必ず出した状態で始め、前後に送ったときは状態を
保つ。帯を消したまま写真をめくり続けられるようにするためである。出し入れに
アニメーションは付けない。

| 押した場所 | 動き |
|---|---|
| 戻るボタン | 閉じる（`requestClose`） |
| 前・次のボタン | 送る |
| 動画（`controls` あり） | 何もしない。ブラウザに任せる |
| 動画（`controls` なし） | 帯を出す |
| それ以外（写真、黒い余白、帯の空いた所） | 帯の出し入れを切り替える |

今までは写真をタップすると閉じていた。タップを出し入れに使うので、閉じる操作は
戻るボタン、下スワイプ、Esc、ブラウザの戻るになる。PC でもクリックで出し入れし、
マウスの動きで自動的に出したり、時間で消したりはしない。

キーボード（Esc、← →）とスワイプ（左右で送る、下で閉じる）は変えない。

## 動画

標準コントロールを使い、`controls` を帯と連動させる。帯を出しているときだけ付ける。

自前のコントロールにすれば帯と一緒に出入りし、タップの意味も写真と揃うが、
シークバーのドラッグや時間表示などで JS が大きく増えるので採らない。動画の表示域を
帯の分だけ縮めて重なりを避ける案も、動画が縮むので採らない。

標準コントロールは画面の下端ではなく動画の下端に描かれる。横長の動画を縦向きの
スマホで見ると、動画は画面の中ほどで終わり、左下の文字とは重ならない。そこで
重なるときだけ文字を上げる。動画の下端から 4rem の帯（コントロールの目安）と
左下の文字の矩形が交わるときに `raised` を付け、`bottom: calc(4rem +
env(safe-area-inset-bottom))` にする。常に上げると、重なっていないのに文字が浮いて見える。

判定は次のときに行う。

- 帯を切り替えたとき
- `/info` が届いて文字が入ったとき
- `ResizeObserver` が lightbox か動画の大きさの変化を知らせたとき（メタデータが届いて
  動画の大きさが決まったとき、画面を回転させたとき）

標準コントロールを使うことで、次は受け入れる。

- 帯を出しているときに動画をタップすると、帯の出し入れではなくブラウザの動きになる
  （PC は再生／一時停止、スマホはコントロールの出し入れ）。
- 4rem は目安で、ブラウザによって少し隙間が空いたり近すぎたりする。
- 再生中はブラウザの判断でコントロールが消え、帯は出ているのにコントロールだけ
  無い状態になる。

## 実装

### HTML（index.html）

```html
<div id="lightbox" class="lightbox chrome" hidden>
  <img alt="">
  <video playsinline preload="metadata" hidden></video>
  <p class="lb-error" hidden>この端末では再生できません</p>
  <div class="lb-top">
    <button class="lb-back" type="button" aria-label="戻る">←</button>
  </div>
  <div class="lb-caption">
    <p class="lb-owner" hidden></p>
    <p class="lb-when" hidden></p>
  </div>
  <button class="lb-nav lb-prev" type="button" aria-label="前へ">‹</button>
  <button class="lb-nav lb-next" type="button" aria-label="次へ">›</button>
</div>
```

`<video>` の `controls` は JS が付け外しする。

### CSS（app.css）

- `.lightbox:not(.chrome)` のとき `.lb-top`、`.lb-caption`、`.lb-nav` を隠す。
- `.lb-top` は上端いっぱいに置き、`pointer-events: none` にしてボタンだけを押せる
  ようにする。帯の空いた所を押すと写真を押したのと同じになる。
- `.lb-caption` は左下に置き、`pointer-events: none` にする。
- `.lb-caption.raised` は上の `bottom` にする。
- `.lb-nav` は上の丸いボタンにし、タッチ端末では出さない。今の左右 22% の透明な
  領域と、それをシークバーから避ける `.lightbox.playing .lb-nav { bottom: 4rem }` は
  やめる。

### JS（lightbox.js）

```js
function setChrome(on) {
	box.classList.toggle("chrome", on);
	vid.controls = on;
	placeCaption();
}

const CONTROLS_H = 64; // 標準コントロールの高さの目安。app.css の 4rem と揃える

function placeCaption() {
	caption.classList.remove("raised");
	if (vid.hidden || !vid.controls) return;
	const c = caption.getBoundingClientRect();
	const v = vid.getBoundingClientRect();
	const hit = c.bottom > v.bottom - CONTROLS_H && c.top < v.bottom
		&& c.left < v.right && c.right > v.left;
	caption.classList.toggle("raised", hit);
}
```

`onBoxClick` は「操作」の表のとおりに振り分ける。

`showOwner` は `showInfo` にする。`/info` から撮影者と日時を取り、それぞれの行に
入れる。撮影者が無ければ 1 行目を隠す。写真を送るたびに 2 行とも空にしてから
取り直すのは今と同じである。

### 日時の書式（datefmt.js）

「2026年2月8日 14:32」の形にし、今年なら年を省く。一覧の日付ラベル
（`gallery.js` の `formatDay`）と同じ規則なので、`formatDay` を新しい `datefmt.js`
に移し、日時用の関数と並べて一覧と全画面の両方から使う。

`takenAt` は `new Date(...)` に渡さず、数字に分解して使う。時差の無い文字列を
ブラウザに解釈させると、書式によっては UTC として扱われてずれる。表示に要るのは
年・月・日・時・分の数字だけである。

### サーバー（view.go）

`/info/{id}` の応答に撮影日時を足す。

```go
type infoView struct {
	Owner   string `json:"owner,omitempty"` // 撮影者の名前
	TakenAt string `json:"takenAt"`         // "2006-01-02T15:04:05"。撮影地の時刻で、時差は持たない
}
```

値は `m.TakenAtLocal()` をそのまま入れる。列は NOT NULL なので常にあり、
`omitempty` は付けない。`/tiles` には足さない。一覧で要るのは日付だけで、今の
`date` で足りている。

## テスト

既存のブラウザテストは、閉じる操作を Esc、下スワイプ、ブラウザの戻るで確かめて
おり、写真のタップで閉じることには頼っていない。書き換えは要らない。

web_test:

- `/info/{id}` の `takenAt` が取り込んだ時刻の文字列と一致する。

browser_test:

1. 写真を開くと `chrome` が付いている。写真をクリックすると外れて左下の文字と
   戻るボタンが見えなくなり、もう一度で戻る。前に送っても状態が保たれる。
2. 戻るボタンを押すと閉じ、URL が `/` に戻る。
3. 過去の年に撮った写真を開くと、2 行目に「2020年9月13日 21:28」の形で出る。
   過去の年にするのは、実行した年で年の有無が変わらないようにするためである。
4. 動画を開くと `controls` が付いている。動画の外側をクリックして帯を消すと外れ、
   動画をクリックすると帯が戻って `controls` も付く。
5. 中身の無い動画は既定の 300×150 で表示される。1200×900 の画面では動画が中央で
   終わるので `raised` が付かず、300×150 の画面では下端まで届くので付く。
6. `(hover: hover)` の環境（ヘッドレス Chrome）で前後のボタンが見えていて、
   クリックすると送れる。

JS の単体テストの仕組みはリポジトリに無いので作らない。`datefmt.js` は 3 と、
既存の一覧の日付ラベルのテストを通して確かめる。
